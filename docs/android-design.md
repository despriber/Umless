# Umless Android 设计文档

> 一个完整的中文输入法，语音输入是它的核心功能。说完自动去口癖、纠错、排版，同时积累逐字稿，供表达教练使用。

## 1. 关键决定

| 问题 | 决定 | 原因 |
|---|---|---|
| 产品形态 | 完整输入法（含拼音键盘），不做悬浮球、不做纯语音面板 | 纯语音面板需要和其他输入法来回切换，切回 Umless 很麻烦 |
| 技术底座 | fork [fcitx5-android](https://github.com/fcitx5-android/fcitx5-android) | 拼音成熟（全拼 / 双拼 / 搜狗词库导入）、维护活跃、Kotlin + C++ |
| 许可证 | Android 端按 LGPL-2.1 发布；桌面端保持 MIT | fcitx5-android 是 LGPL；不做闭源商业版，所以没有影响 |
| 仓库 | 单独仓库（如 `Umless-Android`），本仓库只放设计与共享规范 | 两种许可证分开管理；方便跟进上游 |
| 语音识别 | sherpa-onnx（Apache-2.0）+ SenseVoice-Small int8，本机运行 | 与桌面端默认引擎一致，可离线 |
| 润色 | 用户自己的 OpenAI 兼容接口，与桌面端相同 | 与桌面端一致，不提供官方托管服务 |

上游现状（2026-10）：fcitx5-android 没有内置语音识别，工具栏的麦克风按钮只能跳转到其他语音输入法（#824 已合并）；用系统 SpeechRecognizer 的方案（#899、#965）还没合并；issue #962 提出的 sherpa-onnx 方案可以作为参考。

## 2. 架构

```
┌──────────────── 输入法进程（fcitx5-android 改造）────────────────┐
│ 拼音键盘 / 候选栏（上游）                                          │
│ 长按空格 → 录音 → [AIDL] → 识别 → 场景识别 → LLM 润色 → 写入输入框   │
│                                   └→ 规则指标 → 本地数据库         │
└───────────────┬─────────────────────────────────┬────────────────┘
                │ AIDL                            │ 共享数据库
┌───────────────┴──────────────┐   ┌──────────────┴──────────────────┐
│ :voice 独立进程               │   │ 主 App（设置 / 教练）            │
│ sherpa-onnx + SenseVoice      │   │ 新手引导 · 概览 · 报告 · 练习    │
│ 原生崩溃不影响键盘             │   │ 历史 · 设置 · 模型下载 · 导出    │
└──────────────────────────────┘   └─────────────────────────────────┘
```

- **改动尽量集中**：Umless 的代码放在独立的 Gradle 模块和包名下（如 `org.umless.*`），对上游代码只做最少的接入改动（空格长按、工具栏按钮、设置页入口），方便以后合并上游更新。
- **识别放在 `:voice` 进程**：原生库崩溃或内存不足时不会拖垮键盘；不用语音时可以释放内存（参考 #962 的方案）。
- **应用 ID 与上游不同**（如 `org.umless.ime`），可以和原版 fcitx5 同时安装。

## 3. 语音输入

### 3.1 交互

1. **两个入口，都是按住说话**：
   - **长按空格**（主入口，与讯飞、搜狗的习惯一致）：在上游的「空格长按行为」里新增「Umless 语音」，并设为默认；上游原有的选项保留，用户可以改回。空格左右滑动移动光标的功能不受影响（滑动不算长按）。
   - **工具栏的麦克风按钮**：上游原本用它跳转到其他语音输入法，改为打开 Umless 的语音面板（大按钮按住说话，适合长段口述、单手操作），面板上也能看到最近一次的原话和润色结果。

   不新增独立按键、不改动上游的字母键盘布局。按住后立即开始录音，键盘上方显示「正在聆听」和实时声波。
2. **松开**：候选栏依次显示「识别中」「润色中」。
3. **写入**：润色结果直接写入输入框（`commitText`），不需要模拟粘贴。
4. **可撤销**：写入后候选栏短暂显示「原话 / 撤销」，点一下就能换回识别原文，或者全部撤销。
5. **上滑取消**：按住时手指上滑松开，就是取消这次输入（与常见聊天软件一致）。

和桌面端一样，第一版等一句话说完、整段识别后再润色（润色需要完整的上下文）。边说边出字放到以后再考虑。

### 3.2 失败兜底

- LLM 超时、未配置或没有网络时，直接写入识别原文（只做本地的口癖词删除），并在候选栏提示。
- 模型未下载时，触发语音会提示并跳转到下载页。
- 延迟目标：10 秒以内的一句话，从松开到写入少于 2 秒（识别约 0.5 秒 + LLM）。

### 3.3 场景识别

输入法能拿到当前 App 的包名和输入框类型（`EditorInfo`），比桌面端更准：

| 场景 | 判断依据 |
|---|---|
| 聊天 | 包名：微信、QQ、钉钉、飞书、Telegram 等 |
| 文档 | 包名：WPS、Notion、Obsidian、备忘录等；多行长文本框 |
| 邮件 | 输入框类型为邮件正文；包名：Gmail、Outlook 等 |
| 搜索 / 网址 | 输入框类型为搜索、URI：只用「忠实」档，不分段 |
| 默认 | 其他 |

润色强度、各场景风格和硬约束（不新增信息，数字、人名、否定、时间原样保留）与桌面端一致，提示词直接使用 `spec/prompts/`（见第 7 节）。

## 4. 隐私

- **密码框**（`inputType` 为密码类）：长按空格不触发语音、隐藏麦克风按钮，不记录。
- **无痕模式**：输入框带 `IME_FLAG_NO_PERSONALIZED_LEARNING` 标记（如浏览器无痕标签页）时，照常输入，但不记录。
- **应用黑名单**：默认包含常见的密码管理器和银行类 App。
- 录音不保存；逐字稿只存在本机数据库；支持保留天数、导出、清空。
- **网络权限**：上游没有 INTERNET 权限，我们必须加上（用于 LLM 和模型下载）。只连接用户配置的 LLM 地址和模型下载地址，并在设置和 README 里写清楚。

## 5. 模型

- 不打包在安装包里。首次使用时在 App 内下载（显示进度、校验 sha256），也支持从文件导入。
- 默认使用 SenseVoice-Small int8（中英日韩粤）。其他模型以后再说（手机上 Qwen3-ASR 太大）。

## 6. 表达教练（主 App）

功能与桌面端一致，页面改为手机布局：

- **概览**：今日输入量、节省时间、综合分趋势、进行中的习惯、高频口癖。
- **报告**：每日诊断、习惯卡（自动诊断前一天，在打开 App 或充电空闲时执行，不在键盘进程里运行）。
- **练习**：每日 5 题，在 App 内录音（不需要键盘）。
- **历史**：原文高亮口癖、重复、改口，可搜索、删除。

界面复用桌面端的网页界面（`desktop/umless/ui/web/`），在 WebView 中加载，两端外观一致；手机屏幕下自动切换为底部标签栏布局。桥接协议与平台差异见 [ui-api.md](ui-api.md) 第 7 节「Android 桥接」。

## 7. 共享规范（在本仓库）

桌面端（Python）和 Android 端（Kotlin）是两套实现，为了让统计和评分结果逐字节一致，本仓库有 [`spec/`](../spec/README.md)（spec 是事实来源：先改 spec，再改两端，样例在两端都通过）：

- [`spec/metrics.md`](../spec/metrics.md)：字符规范化、difflib 复刻、口癖 / 重复 / 改口判定、高亮、汇总与各项评分的精确算法，以及移植要点（按码点处理、HALF_EVEN 取整、Neumaier 求和）。
- [`spec/constants.json`](../spec/constants.json)：词表、权重、阈值、公式系数、指标版本。
- `spec/cases/{metrics,scores,prompts}/*.json`：由桌面端生成的黄金样例（`spec/tools/gen_metrics_cases.py`），两端测试都读这批样例。
- [`spec/prompts/`](../spec/prompts/README.md)：全部提示词纯文本及拼装规则；搜索场景 `scene_search.txt` 只有 Android 使用。

## 8. 里程碑

| 阶段 | 内容 | 完成标准 |
|---|---|---|
| M0 | 共享规范：从桌面端抽出 `spec/` 和测试样例 | 桌面端测试改为读取样例并通过 |
| M1 | fork、在本机编译、改应用 ID 和名称 | 真机上能装、能用拼音打字 |
| M2 | 长按空格说话 + `:voice` 进程 + 模型下载，写入识别原文 | 在微信里按住说话能输入原文 |
| M3 | LLM 润色 + 场景 + 撤销 + 失败兜底 + 设置页 | 日常可用的语音输入法 |
| M4 | 记录、规则指标、历史页、隐私控制 | 数据与桌面端规则一致（样例测试通过） |
| M5 | 每日诊断、习惯卡、概览、口语练习 | 功能对齐桌面端 |
| M6 | 新手引导、中英文界面、发布（GitHub Releases，可考虑 F-Droid） | 首个公开版本 |

## 9. 风险

- **在 Windows 上编译**：需要 NDK、CMake、extra-cmake-modules、gettext，还要开启开发者模式和 Git 符号链接。如果太麻烦，改用 WSL2 编译。M1 先把这一步打通。
- **跟进上游**：改动集中在独立模块，定期合并上游。
- **内存与后台**：识别模型约几百 MB，放在 `:voice` 进程，不用时释放；国产系统可能杀进程，需要测试冷启动延迟。
- **LLM 延迟**：网络慢时体验差。设置超时，超时后写入原文，润色结果来了也不再替换（避免打乱用户正在编辑的内容）。

## 10. 已定的细节

- **语音入口**：长按空格（默认）+ 工具栏麦克风按钮打开语音面板，见 3.1。理由：长按空格是国内主流输入法的习惯，不占键位；上游已有「空格长按行为」设置和工具栏语音按钮，接入改动最小。
- **双端数据同步**：不做（与「数据只在本地」原则一致）。
- **开发环境**：Windows 原生编译（不用 WSL），需要 JDK 21、Android SDK / NDK 28 / CMake 3.31.6、MSYS2（提供 extra-cmake-modules 和 gettext）、Android Studio。
- **调试设备**：至少一台国产 ROM 真机（如 ColorOS / HyperOS），重点测试后台被杀和冷启动延迟。
