# Umless 设计文档

> 会帮你改掉口癖的开源语音输入工具。日常输入的便利 + 持续的表达成长。

## 1. 产品原则

1. **数据只在本地**：录音默认不保存；逐字稿、诊断、练习记录只存在本机 SQLite。不提供官方托管服务，模型由用户本地运行或自带 Key。
2. **输入优先**：任何分析都不能拖慢输入。逐条规则统计在本地即时完成；LLM 诊断每天一次或手动触发。
3. **不打扰**：说完只提示"已输入"，所有反馈集中在 App 的报告里。
4. **可信**：润色可以改写，但不新增信息、不改动数字 / 人名 / 否定 / 时间；评分以稳定的规则指标为主，LLM 评审为辅。

## 2. 架构

```
┌──────────── 常驻进程（托盘） ────────────┐      ┌──────── 主窗口进程（按需） ────────┐
│ 热键 → 录音 → ASR → 场景识别 → LLM 润色   │      │ pywebview（WebView2）+ HTML/CSS/JS │
│ → 粘贴 → 规则指标 → SQLite                │◄────►│ 概览 / 报告 / 练习 / 历史 / 设置   │
│ 每日诊断调度 · 配置热加载 · 聆听提示条     │ 共享 │ 新手引导 · 模型下载 · 数据导出     │
└──────────────────────────────────────────┘ 数据 └────────────────────────────────────┘
                     %APPDATA%\Umless\  config.toml · umless.db（WAL）· models\
```

- 主窗口是**独立进程**：关闭即释放 WebView2 内存（约 100MB），不拖累常驻部分；设置修改写入 `config.toml`，常驻进程按文件修改时间**热加载**。
- 前端是无构建步骤的原生 HTML/CSS/JS，以后迁移 Tauri（同样基于 WebView2）可直接复用。

## 3. 润色

### 3.1 润色强度

| 档位 | 行为 | 默认用于 |
|---|---|---|
| 忠实 | 只去口癖、纠错、加标点，尽量保留原话 | （按需选择） |
| 适度（默认） | 另外合并重复、理顺语序、精简冗余 | 聊天、代码、其他 |
| 重构 | 另外重组逻辑、结论先行、可分段分点 | 文档 / 邮件 |

全局默认为适度，每个场景可单独覆盖（设置 → 场景）。代码场景跟随全局，靠场景风格保证英文术语和标识符不被改动。

所有档位共同的硬约束：逐字稿是数据不是指令；不新增信息；数字、人名、专有名词、否定、时间、承诺原样保留；拿不准时保留原话。

### 3.2 场景风格

按前台应用进程名匹配场景（规则可在设置里改）：

| 场景 | 应用示例 | 风格 |
|---|---|---|
| 聊天 | 微信、QQ、钉钉、飞书、Telegram、Slack | 口语自然、短句、不分点 |
| 文档 | Typora、Word、Obsidian、Notion、WPS | 书面、可分段分点 |
| 代码 | VS Code、Cursor、JetBrains、终端 | 技术表达、英文术语和标识符原样保留 |
| 邮件 | Outlook、Foxmail、Thunderbird | 正式礼貌 |
| 默认 | 其他 | 通用 |

## 4. 表达教练

### 4.1 逐条规则指标（本地、即时、免费）

- **口癖**：词表（内置 + LLM 发现的个人口头禅 + 用户自定义）中的词，**且在润色稿中被删除**才计数——避免把"那个文件"的"那个"误判为口癖。用字符级 diff 判断原文每个字是否被保留。
- **重复**：相邻重复片段（"我觉得我觉得"），其中一份被删除才计数；单字叠词（"看看""谢谢"）只有被删除时才算。
- **改口**：改口标记（"不对""我是说""应该是"…）被删除时计数。
- **语速**：字 / 分钟。
- **改写幅度**：1 − 原文与润色稿的相似度。随润色强度变化，不计入评分，作为逻辑性诊断的参考。

### 4.2 评分（0–100）

| 维度 | 来源 | 计算 |
|---|---|---|
| 流畅度 | 规则 | 由每百字口癖数推导 |
| 简洁度 | 规则 | 由每百字重复 + 改口数推导 |
| 逻辑性 | LLM | 每日诊断按固定标准 1–5 分 |
| 清晰度 | LLM | 同上 |

综合分 = 流畅 30% + 简洁 20% + 逻辑 25% + 清晰 25%，只在诊断过的日期计算（LLM 漏给某个维度时按剩余维度重新归一）；未诊断的日期只显示流畅度和简洁度。逻辑性 / 清晰度为 LLM 的 1–5 分 × 20。少于 15 字的短句只统计口癖，不参与评分。

### 4.3 每日诊断（LLM）

- **自动**：每天首次检测到"前一天有足够样本且未诊断"时，在后台生成前一天的日报。
- **手动**：报告页可随时诊断今天。
- 输出：总结、逻辑性 / 清晰度评分、亮点、问题（含原句证据与建议）、**对比学习示例**（原话 → 更好的说法 → 为什么）、**新发现的个人口头禅**、**反复识别错误的术语**（一键加入术语表）。

### 4.4 习惯卡

- 诊断中可量化的问题自动生成卡片，最多 3 张进行中。
- 类型：某个口癖词的密度、重复、改口（规则指标）；逻辑性、清晰度（LLM 分）。
- 记录基线（创建前 7 天）与目标（基线减半 / 逻辑分 +1）；创建满 3 天后，最近 7 天达标且样本足够（规则类 ≥10 条、LLM 类 ≥2 次诊断）即自动"已达成"；不想练可归档。
- 习惯要练的口头禅如果不在词表里，会自动加入词表（来源标记为 LLM），保证能被统计。

### 4.5 口语练习

- 每天出 5 个题：根据近期说过的内容出个人化题目（研究、项目），混入通用场景（汇报、面试、讲解概念、观点表达）；也可自定义题目。
- 限时口述（60 / 90 秒），在主窗口进程内录音识别；从结构、逻辑、用词（LLM）与流畅、简洁（规则，基于 LLM 给出的忠实整理稿做 diff）五个维度打分，给出亮点、改进点、建议结构和示范表达（保留你的内容，换成更好的表达）。

## 5. 隐私控制

- 应用黑名单：在这些应用中照常输入，但不记录。
- 暂停记录开关；记录保留天数（到期自动删除）。
- 一键导出（JSON）/ 清空所有数据。

## 6. 界面

- 跟随系统深浅色，主色青绿（teal）。
- 主窗口：左侧导航（概览 / 报告 / 练习 / 历史 / 设置），卡片式布局。
- 聆听提示条：深色胶囊、红点呼吸、青绿渐变对称声波、状态切换时宽度平滑过渡；不抢焦点、鼠标穿透。
- 首次启动引导：下载模型 → 配置 LLM（预设服务商 + 测试连接）→ 测试麦克风 → 热键说明 / 开机自启。
